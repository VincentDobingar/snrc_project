Le seul constat important non corrigé — et pourquoi

Vidéos de discours officiels sans sous-titres (src/pages/public/Home.jsx). Ajouter de vrais sous-titres nécessite une transcription fidèle de ce qui est réellement dit dans chaque vidéo — un travail de contenu, pas de code. Générer des sous-titres inventés ou approximatifs sur des discours officiels d'un ministre et d'une directrice générale serait irresponsable (risque de citation erronée). Ce point reste donc volontairement ouvert : il faut une transcription humaine des deux vidéos, puis un fichier .vtt par vidéo — happy to wire up the <track> element as soon as the transcripts exist.

Sécurité 3

Mineur Énumération d'emails admin possible par mesure du temps de réponse au login
src/controllers/auth.controller.js:24-43

login() renvoie 401 immédiatement si l'email est inconnu, mais exécute un bcrypt.compare coûteux si l'email existe — la différence de temps de réponse permet de déterminer si un email correspond à un compte admin existant.

Recommandation — Exécuter un bcrypt.compare factice sur le chemin "utilisateur introuvable".

Mineur Aucune protection contre le brute-force distribué (uniquement par IP)
src/middlewares/rateLimiters.js:3-12

Un attaquant répartissant ses tentatives sur plusieurs IP n'est pas ralenti pour cibler un compte précis.

Recommandation — Ajouter un compteur d'échecs par compte (email) en complément du rate-limit par IP.

Mineur Attribut style autorisé sans restriction sur tout le HTML riche admin
src/middlewares/sanitizeHtmlFields.js:5-14

Un contenu admin peut injecter du CSS arbitraire sans exécuter de script, avec un risque de défiguration/spoofing visuel si un compte éditeur est compromis.

Recommandation — Restreindre style à une liste blanche de propriétés via allowedStyles.
